# Evaluation report

## Approach

The document level run actually uses a two part evaluation system.

1) I manually reviewed the prospectus's contact and management sections to identify the PII categories actually present, then checked that the original values were absent from the generated DOCX (including all hidden `mailto:`/`tel:` Word field instructions).
2) I ran the `python evaluate.py` script which is a labelled, controlled test set that calculates accuracy, precision, and recall. It contains one positive example for each supported type (name, email, phone, address, organisation, DOB, IP, SSN, and card) and nine different negative controls (corporate identity number, SEBI registration number, fiscal year, ordinary date, order number, invalid card, invalid IP, non-PII capitalised phrase, and short numeric ID).

This split is very important: the supplied prospectus is not a fully labelled ground-truth corpus, so claiming an exact corpus-wide precision/recall would be quite a bit misleading.

## Executed prospectus run

Command used:

python redact.py "Red Herring Prospectus.docx" "Red Herring Prospectus - Redacted.docx"


The final run produces the following type of audit counts. Occurrences includes all the repeated values while unique values are distinct replacement mappings.

| Type | Occurrences redacted | Unique values redacted |
| --- | ---: | ---: |
| Full names | 202 | 35 |
| Email addresses | 122 | 41 |
| Phone numbers | 49 | 33 |
| Company names | 172 | 74 |
| Physical/mailing addresses | 19 | 13 |
| SSNs, credit cards, DOBs, IP addresses | 0 | 0 |

The prospectus did not contain any of the following -  
SSNs, payment-card numbers, IP addresses, or fields marked as dates of birth. 
Ordinary corporate dates were deliberately retained. 
Validation confirmed that inside the output file all 26 inventoried email addresses, sampled phone formats, all nine management-table names, the issuer names, and both registered or corporate office addresses are absent from both the displayed document text and the Word hyperlink targets.

## Controlled-set metrics

| Metric | Calculation | Result |
| --- | --- | ---: |
| True positives | Sensitive test values redacted | 9 |
| False positives | Negative controls redacted | 0 |
| False negatives | Sensitive test values not redacted | 0 |
| True negatives | Negative controls retained | 9 |
| Accuracy | `(TP + TN) / (TP + FP + FN + TN)` | **100.0%** |
| Precision | `TP / (TP + FP)` | **100.0%** |
| Recall | `TP / (TP + FN)` | **100.0%** |

These figures are generated by the evaluate.py script and demonstrate correct rule behavior on the labelled test set but this is not a claim that any arbitrary documents will score 100%. The document-run inventory and all the residual checks provide the complementary evidence for this specific prospectus only.

## Scope and trade-offs

Public corporate contact details were treated as PII for this assignment. Corporate identity numbers, registration numbers, share/application numbers, financial amounts, fiscal years, and ordinary transaction/incorporation dates were retained. The solution is intentionally conservative for ambiguous names, companies, and addresses: it uses explicit labels/table columns and legal-entity/address patterns instead of masking every capitalised phrase. For production, I would add a reviewed entity dictionary, an NER model, and human review for uncertain detections.
